# v1: Guest Voice Studio（お客様の声・改善管理Webアプリ）試作版 [アーカイブ]

`customer_voice_requirements.docx` の要件定義書に基づく MVP 試作品です。
35拠点のアンケート（5段階評価＋自由記述）CSVを取り込み、分析・改善課題管理・
期間比較・PDF報告書・Outlook下書き連携までを、ビルド不要の単一Webアプリとして実装しています。

## 公開URL（GitHub Pages・v1アーカイブ）

**https://haposyan.github.io/guest-voice-studio/**

社外の人にも共有できる公開URLです。ログイン画面でユーザーを選び、Import画面で
`data/sample_35stores.csv` を取り込むとすぐに機能を試せます。

> 注意：データは各自のブラウザのlocalStorageに保存される試作用の簡易実装です。
> 他の人がこのURLを開いても同じデータは共有されません（人ごと・端末ごとに別データになります）。
> 複数拠点でデータを共有するには、サーバーDB化が必要です（詳細は下記「既知の制限」参照）。

## 起動方法（ローカルで動かす場合）

ビルドは不要ですが、**`index.html` を `file://` で直接ダブルクリックして開くと空白ページになります**。
本アプリは ES Modules（`<script type="module">`）を使っており、Edge/Chromeは `file://` オリジンからの
モジュール読み込みをCORSでブロックするためです（Chromium系ブラウザ共通の仕様で、本アプリ固有の不具合ではありません）。

同梱の簡易ローカルサーバー（PowerShell、追加インストール不要）で配信してから開いてください。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\serve.ps1 -Port 8843
```

起動後、Edgeで `http://localhost:8843/` を開きます。社内配信する場合も同様に、何らかのWebサーバー
（IIS／Nginx／社内Webホスティング等）から配信する構成にしてください（§7 運用要件「中央配信のWebアプリ」とも合致します）。

初回起動時に35拠点・5項目・4名のサンプルユーザーが自動的に作成されます（`js/db.js`）。
ログイン画面でユーザーを選択するだけで各役割（本部管理者／拠点責任者／閲覧者）の見え方を確認できます。

### サンプルデータで試す

`data/sample_35stores.csv`（UTF-8, 912件, 35拠点×2ヶ月分）と
`data/sample_35stores_sjis.csv`（同内容のShift-JIS版、文字コード判定確認用）を用意しています。

1. ログイン（本部管理者を選択）
2. 左メニュー「Import｜CSV取込」→ `data/sample_35stores.csv` をドラッグ＆ドロップ
3. プレビューを確認して「この内容で取り込む」
4. 「Guest Voice｜お客様の声」「Compare｜期間比較」「Lobby｜ダッシュボード」でデータを確認

サンプルCSVは `scripts/generate_sample.ps1`（PowerShell）で再生成できます。意図的に重複行を2件含めており、
重複排除（IMP-04）の動作確認に使えます。

## アーキテクチャ

- ビルド不要の素の HTML / CSS / ES Modules（`<script type="module">`）。Node/npm が使えない環境でも動作するよう意図的に依存ゼロにしています。
- `js/db.js`：データ層。**現状は localStorage を「試作用DB」として使用**しています。本番は認証済みAPI経由のサーバーDBに置き換える前提です（§7 機密性要件）。
- `js/csv.js`：文字コード判定・CSVパース・拠点名寄せ・重複排除。
- `js/tokenizer.js`：簡易日本語語抽出（下記「既知の制限」参照）。
- `js/analysis.js`：集計・比較ロジック（表示ロジックと分離。§Claude Codeへの実装指示 準拠）。
- `js/screens/*.js`：画面ごとのUI。
- 外部通信・外部AI・CDNは一切使用していません（§7 外部送信要件、コメント原文を外部送信しない方針に準拠）。

## 既知の制限・簡略化した点（正直に明記）

- **形態素解析なし**：`js/tokenizer.js` は kuromoji.js 等の辞書ベース解析器を使わず、
  漢字・カタカナの連続を語として抽出する簡易ロジックです（この実行環境に npm/Node が
  無く、外部ライブラリを取得できなかったため）。日本語のカスタマーコメントでは
  多くの場合これで実用的な頻出語が拾えますが、助詞処理や複合語分割の精度は
  本格的な形態素解析に劣ります。第4段階（高度化）でのアップグレードを推奨します。
- **PDF生成はブラウザの印刷機能を利用**：PDFライブラリを同梱していないため、
  Report Studio の「PDFとして保存」は印刷用CSSを適用した画面を `window.print()` で
  開き、Edge/Chromeの「PDFに保存」機能で書き出す方式です。実運用相当の見た目ですが、
  サーバーサイドPDF生成（Puppeteer等）への置き換えも可能です。
- **Outlook連携はmailtoフォールバックのみ**：Microsoft 365 Graph API等への接続は
  行っていません（MAIL-04は未接続）。「Outlookで下書きを作成」ボタンは MAIL-05 の
  代替フローに従い、宛先・件名・本文を埋めたメール作成画面を開きます。PDFの添付は
  手動です。本番でのMicrosoft 365連携は管理者承認後に別途実装が必要です。
- **認証は簡易モック**：ログイン画面はユーザー一覧から選択するだけです。本番は
  Microsoft 365／会社アカウント連携が前提（AUTH-04、要確認事項）。
- **永続化はブラウザのlocalStorage**：複数端末・複数拠点での共有はできません。
  本番はサーバーDB＋API化が必須です。データ量が多い場合の性能も未検証です。
- **通知・重大性の自動検知（第4段階）は未実装**：安全・衛生等の重大コメントは
  Action Board 上で人が「重大フラグ」を手動で立てる方式にとどめています
  （断定・自動対応をしないという§5.2の方針に合わせた設計判断）。

## 要確認事項と、この試作での扱い（§11 対応表）

| 確認事項 | この試作での扱い |
|---|---|
| 日次CSVの範囲（新規/累積） | 回答IDベースの重複排除を必須化。どちらの運用でも二重集計されない |
| 一意な回答ID | あれば使用。無い場合は合成ID（`NOID-<batch>-<行番号>`）を発行し「要確認」として警告表示 |
| CSV列構成 | サンプルCSV・列マッピング仕様を同梱（`data/sample_35stores.csv`、Settings＞項目マッピング） |
| ホスティング | クラウド非依存。静的ファイルのみで動作 |
| 認証 | 試作は簡易認証（ユーザー選択式）。本番はMicrosoft 365前提 |
| データ保存期間 | Settings＞ブランド・保存設定 で日数を設定可能（初期値1095日） |
| 原本保存 | 初期値は非保存。CSV取込画面・Settingsでオン/オフ可能 |
| コメントの属性・少数集団特定防止 | 本試作のサンプルCSVには年代等の属性列を含めていない（属性を扱う場合は閾値設計が別途必要） |
| Microsoft 365許可 | 未接続。mailtoフォールバックで代替 |
| ブランド情報 | Settings＞ブランド・保存設定 で会社名・ドメインを設定し、報告書に反映 |

## 次のステップ（推奨）

1. 実際のCSVサンプルを使い、列マッピング・拠点表記ゆれ・重複排除の挙動を検証する
2. 形態素解析ライブラリの選定（オフライン辞書が使える kuromoji.js / Sudachi 等）と社内承認
3. サーバーサイドDB・認証API（Microsoft 365連携）への移行設計
4. PDF生成をサーバーサイド化するか検討（現状はブラウザ印刷）
5. 監査ログ・保存期限ポリシーを会社の情報管理規程に照らして最終確定
